## 3. Cost and quota

### Method

- Calls are counted from the code path of each action (client calls → routes → `generate`).
- **Input tokens** come from `scripts/prompt-sizes.ts`, which runs the real routes and prompt builders against fixture answers and measures what each call sends (characters ÷ 4, ±25%). Run it again after prompt changes: `npx tsx scripts/prompt-sizes.ts`.
- **Output tokens are my estimate of the visible answer** (JSON the app displays). **Thinking tokens are extra and are billed as output**; most calls use `LOW` or `MINIMAL` thinking, so plan for roughly +50–100% on the output column until the logs say otherwise.
- Live voice is audio, not text. I used 32 tokens per second of audio, which is the figure I remember from Google's documentation; **I could not open the pricing page from here, so check the figure and the per-token prices before turning any of this into money.** I have not put prices in this document on purpose.
- Every REST call can be retried up to 3 times on 429/5xx/timeout. Retries are counted in the daily cap and are not in the typical-day numbers (they only happen on failures).

### Background cost, no user needed

Brief ingestion analyses up to 3 new items from each of 8 feeds, one Gemini call per item: **up to 24 calls on every cold start** (the cache is in memory) and a few per 3-hour refresh afterwards. With `min-instances=1` that's a deploy-time cost, not a daily one. Without it, every idle wake-up repeats it.

## 4. Deployment: M-2 and M-3

### M-3: role-play secrets (fixed)

The hidden goal and complication are now sealed into a token (AES-256-GCM, 12-byte random nonce per token, 24-hour expiry) returned with the public scenario and sent back by the browser on each turn and at the debrief. Any instance with the key can open it; the browser cannot read or alter it. A turn whose token is missing, expired, tampered with or sealed by another key gets **HTTP 410 `scenario_expired`** and a message, instead of silently continuing with a generic scenario. The debrief, which grades something that already happened, still works and says plainly that the secrets are unavailable. "Replay with the twist" still works because the learner already holds the twist from the debrief and sends it. The in-memory store (`roleplayStore.ts`) and its 45-minute TTL are gone, and turns no longer build prompts from client-supplied scenario text (the one exception is the replay case above).

- **Key:** `ROLEPLAY_TOKEN_SECRET` (any long random string; comma-separated to rotate, the first seals and all open). Create it once: `openssl rand -base64 32 | gcloud secrets create linguaforge-roleplay-token-secret --data-file=-`. If it is not set, the server generates a random key at startup and logs `roleplay_token_key_ephemeral`: every restart then expires running scenarios.
- Tests: `server/roleplayToken.test.ts` (round trip, hides secrets, other key, rotation, expiry, tamper, fresh nonce) and the role-play flow in `server/app.test.ts`.

### M-2: Brief items in per-instance memory (stopgap)

I did not add a shared store. For a closed beta the simplest safe fix is **one instance**: `max-instances=1` so there is one Brief cache and one set of per-IP counters, and `min-instances=1` so the instance (and its cache) isn't thrown away when idle. The cost is that a deploy or crash re-runs the ≤ 24 Brief analyses, and Live calls drop on a deploy. Before running more than one instance, M-2 needs a shared store (Firestore or Redis) and the per-IP limiters need one too.

| Min / max instances                       | **1 / 1**                                     | M-2 (above); also makes the per-IP and daily counters global.                                                                                                                                                                                           |
| Request timeout                           | **1200 s**                                    | Cloud Run ends a WebSocket at the request timeout. Live sessions are capped at 15 min, so the timeout must be longer. The default 300 s would cut every call at 5 minutes.                                                                              |
| Concurrency                               | 80                                            | One instance serves every tester; Live voice has its own cap of 20.                                                                                                                                                                                     |
| CPU / memory                              | 1 vCPU / 512 MiB                              | 20 audio sessions plus the Brief cache (150 items) fit comfortably.                                                                                                                                                                                     |
| CPU allocation                            | request-based (default), startup CPU boost on | The 3-hour Brief refresh then runs when the next tester opens the app. Use "CPU always allocated" if it must run on schedule.                                                                                                                           |
| `NODE_ENV`                                | `production`                                  | Enables the CSP and static serving; the server refuses `GEMINI_FAKE=1` with it.                                                                                                                                                                         |
| `TRUST_PROXY`                             | `1`                                           | One hop (Cloud Run's front end) so limits key on the real client IP. A wrong value makes everyone share one IP or lets a client spoof one.                                                                                                              |
| `GEMINI_API_KEY`, `ROLEPLAY_TOKEN_SECRET` | Secret Manager                                | Not in plain environment variables.                                                                                                                                                                                                                     |
| `APP_URL`                                 | the service URL                               | The WebSocket origin check allows this host (and the request's own host).                                                                                                                                                                               |
| Quota variables                           | see the README table                          | `GEMINI_DAILY_CALL_CAP`, `API_DAILY_LIMIT_PER_IP`, `LIVE_DAILY_SESSIONS_PER_IP`, …                                                                                                                                                                      |
| Health probes                             | `/api/health`                                 | Startup and liveness.                                                                                                                                                                                                                                   |
| Authentication                            | **decide before sharing the URL**             | `ingress: all` and unauthenticated access mean anyone with the link can spend your Gemini quota (within the caps above). For a closed beta, either keep the URL private, or require IAM/IAP and give testers access, or accept the caps as the control. |

Deploy from source with the same settings (flags equivalent to the YAML):

```bash
gcloud run deploy linguaforge --source . --region REGION \
  --min-instances 1 --max-instances 1 --timeout 1200 --concurrency 80 --cpu 1 --memory 512Mi \
  --set-env-vars NODE_ENV=production,TRUST_PROXY=1 \
  --set-secrets GEMINI_API_KEY=linguaforge-gemini-api-key:latest,ROLEPLAY_TOKEN_SECRET=linguaforge-roleplay-token-secret:latest
```

### Deployment risks I did not change

- There is no Dockerfile and no npm lockfile (only `bun.lock`): a buildpack source deploy installs the `^` ranges fresh, so the deployed versions can differ from what CI tested. If that worries you, deploy from a Dockerfile that runs `bun install --frozen-lockfile`. I could not test a container build here.
- The service worker precaches the app. After a deploy, an open phone may keep running the old build until the update prompt is accepted.
- Brief audio and article links go straight to publishers; a publisher that blocks hot-linking shows "Stream unavailable".

## 5. Observability

### Server logs

`server/logger.ts`: one JSON object per line on stdout (`severity`, `message`, `event`, `time`, plus the request's `route` and `requestId` inside a request). Cloud Run's log agent turns it into structured entries.

| Event                                                                                                                  | Severity               | Fields (no user text, ever)                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gemini_call`                                                                                                          | INFO                   | route, model, attempts, ms, promptTokens, outputTokens, thoughtTokens, totalTokens                                                                    |
| `gemini_attempt_failed`                                                                                                | WARNING                | route, model, attempt, kind (`rate_limited`, `unavailable`, `auth`, `model_not_found`, `timeout`, `unknown`), error name/status, scrubbed API message |
| `gemini_failure`                                                                                                       | ERROR                  | route, model, attempts, ms, kind, publicStatus, error name/status                                                                                     |
| `gemini_auth_failed`, `gemini_model_not_found`, `unhandled_error`                                                      | ERROR                  | error name, status, 4 stack frames (no message line)                                                                                                  |
| `api_request`, `api_rate_limited`                                                                                      | INFO / WARNING / ERROR | `METHOD /path` (no query string), status, ms                                                                                                          |
| `client_error`                                                                                                         | WARNING                | see below                                                                                                                                             |
| `live_upgrade_rejected`, `live_start_failed`, `live_upstream_error`, `live_upstream_closed`, `live_daily_cap_reached`  | WARNING / ERROR        | origin host, close code, scrubbed reason                                                                                                              |
| `roleplay_token_key_ephemeral`, `gemini_fake_mode`, `server_listening`, `server_shutting_down`, `brief_refresh_failed` | mixed                  | operational only                                                                                                                                      |

What keeps text and keys out, by construction rather than by care:

- The logger takes named fields only; there is no "log this object" call. Prompts, request bodies, transcripts, model output and IP addresses are never passed to it.
- Every string is scrubbed for Google API keys, bearer tokens, `key=`/`token=` pairs and `api_key`-style JSON, then truncated to 300 characters (`scrubText`).
- Errors go through `describeError`: name, status and stack frames only. The message is included **only** for errors whose text we wrote or that come from Google's API body, scrubbed and cut to 200 characters. A `SyntaxError` message, which quotes the text it failed to parse (it could be the learner's), is never included. Before this change, `console.error('[server] unexpected error:', err)` logged whole error objects.
- Tests: `server/logger.test.ts` (key patterns, SyntaxError, stack), plus the client-error test in `server/app.test.ts`.

### Browser error reports

`POST /api/client-error` (`server/clientErrors.ts`, `src/services/errorReporter.ts`):

- **Sent:** uncaught errors, unhandled promise rejections, React error-boundary crashes, and unexpected audio, speech and Live voice failures (fixed phrases such as "speech synthesis blocked or silent", "websocket closed unexpectedly (1011)", "microphone track ended unexpectedly").
- **Body:** `kind`, a scrubbed message ≤ 300 characters, ≤ 8 stack frames, `tab`, `platform` (`ios` / `android` / `desktop`), `standalone`, `online`, `count`. Anything else in the body is dropped. SyntaxError text is withheld on the client as well.
- **Limits:** 10 reports per minute per IP, 8 KB body, outside the Gemini limiters (a crash loop can't use up the quota), over-limit reports answered `204` and dropped. In the browser: a repeat is sent once and then at most once a minute with a count, at most 20 per page load, no retries, nothing shown to the user. Offline: not sent.
- **Not collected:** conversation text, vocab, storage, URLs, IP, user agent.
- Find them with `jsonPayload.event="client_error"`, then group by `platform`, `standalone` and `message` to see what breaks on which phone.
